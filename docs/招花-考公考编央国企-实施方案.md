# 招花 2.0 · 考公考编 + 央国企招聘信息源实施方案

> 状态：待确认（方案阶段，未改代码）
> 日期：2026-08-18
> 前置背景：招花 M7 第一版已上线（拉勾/猎聘/智联/51job/Boss 浏览器爬虫 + Web/App 招花页 + 设置页 + 按 user_id 隔离）。本方案在现有架构上扩展「考公考编」「央国企」两类官方信息源，并引入「hosts 定位文件」机制。

---

## 一、需求理解

1. 新增两大信息类别：**考公考编**（国考/省考、事业单位、军队文职）与 **央国企**（央企/国企招聘）。
2. 建立一份类似 `/etc/hosts` 的**信息源定位文件（hosts 注册表）**：爬虫只按这份文件里的「地址 + 解析规则」去抓，不写死在代码里。
3. hosts 文件**每周更新**一次（源站改版、新增渠道、选择器维护都通过周更解决，不用改代码）。
4. 前后端 UI 配合：招花页新增分类 Tab + 公告类卡片 + 弹窗；设置页新增类别/信息源/省份配置；移动端对齐。

## 三、Hosts 定位文件设计（核心）

### 3.1 设计理念
把「爬哪些站、去哪页、用什么选择器、什么节奏」全部外置到一份**版本化 JSON 注册表**。代码里只有通用引擎，不再有写死的平台规则。hosts 文件即「信息源的地图」。

### 3.2 文件位置与形态
```
config/job-hosts/
├── sources.json      # 机器可读注册表（爬虫读这份，或读它的 DB 落库）
├── CHANGELOG.md      # 每次更新的变更说明（选择器/URL/新增源）
└── README.md         # 维护手册（如何加源/改选择器/校验）
```

### 3.4 关键设计点
1. **三层语义**：`category`（业务分类 → UI Tab）+ `channel`（内容形态 → 卡片渲染：`job` 职位卡 / `announcement` 公告卡 / `event` 招聘会）+ `engine/selectors`（驱动爬虫）。
2. **引擎抽象**：`engine: http`（轻量 fetch + 正则/cheerio，静态站快且省资源）或 `engine: browser`（Playwright 真实浏览器，过 JS/WAF）。同一套注册表，两种引擎共存。
3. **周更机制**：
   - hosts 文件入库 `config/job-hosts/`（与代码同仓，Git 版本管理 → 天然有历史/回滚）。
   - 服务器 cron **每周一 06:00** 执行 `scripts/update_job_hosts.mjs`：`git pull` 最新 hosts → **JSON Schema 校验** → 落库 `job_crawler_sources` 表 → 更新版本号/时间 → 失败自动回退上一版本并告警。
   - 每次更新后自动触发一次「增量抓取」，把新源数据补进来。
4. **健康度自检**：每次抓取按 source 记录命中率（解析到 ≥1 条 = 命中），低于阈值（如连续 3 次 <30%）在设置页标「需维护」，周更时重点处理。
5. **版本/回滚**：meta.version + DB 存 `applied_version`，坏版本可一键回退。

## 四、数据模型改动

### 4.1 新增表 `job_crawler_sources`（hosts 落库）
```sql
CREATE TABLE IF NOT EXISTS job_crawler_sources (
  id            text PRIMARY KEY,          -- 与 hosts 文件 id 一致
  category      text NOT NULL,             -- internet / gongkao / gongbian / yangqi
  channel       text NOT NULL,             -- job / announcement / event
  name          text NOT NULL,
  engine        text NOT NULL DEFAULT 'http',
  base_url      text NOT NULL DEFAULT '',
  list_config   jsonb NOT NULL DEFAULT '{}',  -- list/pagination/selectors
  detail_config jsonb NOT NULL DEFAULT '{}',
  deadline_parse boolean NOT NULL DEFAULT false,
  rate_limit_ms int NOT NULL DEFAULT 3000,
  max_items_per_run int NOT NULL DEFAULT 20,
  max_pages     int NOT NULL DEFAULT 3,
  risk          text NOT NULL DEFAULT 'L1',
  enabled       boolean NOT NULL DEFAULT true,
  hit_rate      numeric(4,3) NOT NULL DEFAULT 1,
  last_run_at   timestamptz,
  last_error    text NOT NULL DEFAULT '',
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);
```

### 4.2 扩展 `job_postings`
```sql
ALTER TABLE job_postings
  ADD COLUMN IF NOT EXISTS category text NOT NULL DEFAULT 'internet',  -- 业务分类
  ADD COLUMN IF NOT EXISTS channel  text NOT NULL DEFAULT 'job',       -- job/announcement/event
  ADD COLUMN IF NOT EXISTS deadline_at timestamptz,                    -- 公告报名截止（可空）
  ADD COLUMN IF NOT EXISTS extra jsonb NOT NULL DEFAULT '{}';          -- 招录人数/岗位表链接等元信息
```
- `source` 字段保持 text，直接存 `sasac-recruit` / `iguopin` / `mohrss-sydw` 等注册表 id，无需改枚举。
- 公告类卡片字段映射：`title`=公告标题、`company`=发布单位、`city`=地区（可解析则填，否则空）、`salary_text`='—'、`deadline_at`=报名截止、`url`=原文链接、`extra`={recruitCount, examDate, applyStart}。
- 收藏表/用户隔离不变。

## 五、爬虫引擎改动

1. **通用化**：scripts/jobs_browser.mjs 重构为「读 job_crawler_sources 表 → 按 engine 分发」的通用引擎；现有互联网平台规则迁移为 hosts 注册表条目（同一套机制，统一管理）。
2. **http 轻引擎**（新增 scripts/jobs_http.mjs）：fetch + 轻量 DOM 解析（静态站），支持 list + 详情两段抓取，限速/超时/重试沿用现有策略。
3. **公告解析器**（新增模块）：从公告正文/标题提取报名时间/截止时间/考试时间/招录人数/岗位表链接（正则 + 日期归一化），写入 deadline_at 与 extra。
4. **去重与写放大**：沿用 source + source_job_id + content_hash；公告类 source_job_id = 公告 URL 的路径 hash。
5. **配额与节流**：官方源多为低频（每周几条～几十条），总量可控；保持每源限速 + 单源失败不中断全局 + 运行日志按 source 汇总。
6. **周更联动**：update_job_hosts.mjs 更新后自动触发增量抓取。

| POST /api/jobs/run | 支持 category / source 增量抓取 |
| GET /api/jobs/stats | stats 增加按 category 汇总 |

## 八、每周更新与运维（hosts 周更流程）

周一 06:00 cron：
1. git pull config/job-hosts 拉最新注册表
2. schema 校验（失败→回退上一版本+告警，爬虫不受影响）
3. 落库 job_crawler_sources（版本号+时间）
4. 触发增量抓取（新源/变更源补数据）
5. 写 CHANGELOG + 邮件/站内告警（命中率异常源标记）

- 命中率告警（连续 3 次 <30%）→ 设置页标「需维护」→ 维护者改 hosts 选择器 → 提交 → 下周一自动生效。
- 兜底：任何一次更新失败都用上一版本继续跑，绝不因 hosts 损坏停摆。

## 九、风险与边界

1. **公告 ≠ 职位**：公告卡只做「线索收录 + 原文跳转」，不承诺简历投递闭环；详情弹窗明确「请以官方原文为准」。
2. **国考专题站**：强风控 + 季节性，先做公告链接收录 + 原文跳转；职位表 xls 解析列为二期可选。
3. **省级源质量参差**：部分省站有验证码/结构混乱，先开通已验证的江苏/浙江/广东/黑龙江，其他按需扩容。
4. **SPA 站点**（国聘/中智/全国事业单位招聘网）：先用 Playwright 兜底；后续探测其 JSON 接口可显著提速（列入优化项）。
5. **合规**：仅抓取公开公告/职位元信息，原文一律跳转官网；限速节流，尊重 robots 与使用条款。
6. **数据体积**：官方源低频，每周新增有限，无需担心存储与写放大（content_hash 已兜底）。
