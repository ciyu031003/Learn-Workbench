- Mobile：`apps/mobile/src/app/profile.tsx`（新）或并入 settings；数据走 `/api/sync`（如把 profile 作为新同步实体，见下）。

## Phase 2 · 专注计时修正 + 正向计时（秒表）—— 高优先 P0
> 目的：① 后台/前台按墙钟对时不丢时；② 新增「倒计时 / 正向秒表」双模式。
- **Web** `apps/web/components/focus-timer.tsx`（+ 训练/运动模式的 `exercise` 用法，见 `apps/web/lib/autofocus.ts` 与 `/tasks#focus`）：
  - 用 `startRef = Date.now()` 作墙钟基线，`currentElapsed = Date.now() - startRef`（暂停时记 pauseOffset）。
  - **后台按方案 A**：移除「仅 `!document.hidden` 才累计」逻辑，`visibilitychange`/`pagehide` 时用墙钟校正并结算；保留 5s/60s 阈值、12h 上限、`client_id` 幂等、15s 幂等 upsert。
  - 新增模式开关 `mode: 'countdown' | 'stopwatch'`；秒表模式不预设 minutes、只累计 elapsed、可暂停/继续。
- **Mobile** `apps/mobile/src/components/focus-timer.tsx`：
  - 加 `AppState` 监听：回前台时 `remaining = total - (Date.now() - startRef)/1000`（倒计时）或补算 elapsed（秒表）。
  - 加「倒计时 / 正向秒表」双模式 UI。
- 结算写 `apps/web/app/api/focus/route.ts`（现有），distinguish mode 字段可加 `focus_sessions.kind`（迁移可选）或复用 note；**不破坏现有 focus/stats**。
- **验收**：Web/Mobile 切后台再回前台 elapsed 不丢；秒表可记录为专注/运动时长；`/api/focus` 统计不变。
- **回滚**：保留旧计时逻辑开关位；阈值/上限不破坏。

## Phase 5 · Career Radar + /api/jobs/radar（B 为主 + A 兜底）
> 目的：把「单岗位匹配」升级为「个人就业雷达」首页；批量匹配减少逐岗位并发。
- 迁移：**无新表**（纯计算 + 前端聚合；如需持久化用户画像阈值可复用 `user_settings`）。
- Web lib `apps/web/lib/radar.ts`：
  - `computeRadar(userId, { cities, limit })`：一次性拉「目标岗位集（收藏 + 订阅 + 市场推荐）」+ 用户画像（skills/profile city/edu），批量算匹配（复用 `computeJobMatch`/`computeSkillGaps` 的规则正交化，避免 N 次分别查库）；画像缺失时回落逐岗位。
  - 输出：按 `high-match / high-value / urgent-deadline` 分档 + matched/missing + gap 小时数。
- Web API `apps/web/app/api/jobs/radar/route.ts`（GET）+ `route.test.ts`。
- UI：`apps/web/app/career/radar/page.tsx`（新）或升级 `career/market` 上方：「今日就业雷达」Match Ring / 信号卡 / Skill Chips / Region 徽标 / Deadline 徽标；**市场信号卡区只读 `/api/market/*`，不与匹配分混用**。
- Mobile：`apps/mobile/src/app/radar.tsx` 或并入 jobs 页顶部雷达卡。
- **验收**：雷达能批量返回分档岗位；缺画像回落不报错。
- **回滚**：新增 API 带 test；后端表结构不动；可开关新旧首页。
