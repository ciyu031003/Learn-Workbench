## 三、踩坑点（新会话必读）

1. **Windows 仓库大量 CRLF**：apps/web、apps/mobile 部分文件是 CRLF。node 脚本做多行字符串替换时锚点必须含 `\r`（或逐行 split 处理）；锚点匹配失败先查行尾。git 的 LF→CRLF warning 无害。
2. **服务器部署链路**：本地无 rsync → `tar czf - --exclude=... . | ssh tar xzf - -C /home/ubuntu/learn-workbench`，**必须排除** `config/job-hosts`（服务器独有 storageState.json）与 `.env*`，**禁止 --delete**；然后 ssh 跑 `docker compose up -d --build`（deploy-docker.sh 在该服务器因 dash 不支持 pipefail 会挂，直接用 compose）。完整排除清单看 git log 里 6b9bf06 的部署命令。
3. **服务器磁盘**：docker 构建缓存是大头（一次 build 约 6GB 层），连续两次 up --build 就可能打满 60G 盘（报 `no space left on device` 且 compose ps 不变）。急救：杀构建 → `docker builder prune -a -f` → `docker image prune -f` → 重试。已装周日 05:00 cron。注意 travel-notes 的周日 04:30 脚本是全局 prune（docker 层面不分项目）。
4. **数据库迁移只追加不改**：新迁移文件按序号命名放 `db/migrations/`，init 容器幂等执行；**新表必须同步登记 `db/schema.sql`**（`pnpm test:scripts` 的 verify-migrations 会警告未登记表）。种子数据要 `ON CONFLICT DO NOTHING/UPDATE` 保证幂等。
5. **每个 API 路由必须带同目录 `route.test.ts`**（项目铁律）。mock 模式参考既有测试：`vi.mock("@/lib/db")` + `queryMock.mockResolvedValueOnce({rows:...} as never)`。断言多参 SQL 时注意参数是数组整体（`toHaveBeenCalledWith(sql, [a, b])` 而不是逐个）。
6. **next dev 有项目级锁**（`.next/dev`）：僵尸进程会占 3001 端口且不响应 HTTP（curl 超时而非拒绝），还挡住新 dev 启动。本地视觉验收用 `pnpm exec next dev --turbopack -p 3100`；遇到锁先杀占用进程。dev 首次请求触发 Turbopack 编译，curl 超时要给足 120s+。
7. **本地 PostgreSQL**（`scripts/start_pg.ps1`，user=postgres 无密码，db=Learn-Workbench）：Windows 下 pg 可能坏成子进程 `error 487` 无法 spawn——`pg_ctl stop -m fast` 再 `start`；`-o` 里**不能带 `-w`**（那是 pg_ctl 的参数）。
8. **IconPark 图标名陷阱**（生成后必须蒙太奇目检）：`RunLeft`=运行脚本(卡片箭头)不是跑步、`PlayCycle/Cycle`=循环箭头、`Compression`=压缩文件、`Weight`=体重秤、`Stretching`=展开箭头。正确指派：跑步=Sport、拉伸=StretchingOne、俯卧撑=Fitness、平板支撑=Stopwatch、瑜伽=Lotus、八段锦=Kungfu、爬楼梯=Ladder。IconPark 没有自行车/飞盘/太极/仰卧起坐专图（骑行用 lucide Bike 兜底）。本地素材管线在 `.local/iconpark/`（@icon-park/svg 包，fill 数组按路径顺序着色）。
