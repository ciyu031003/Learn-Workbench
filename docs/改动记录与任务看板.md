## 四、已知问题

### 1. 无鉴权头的匿名请求会让部分 API 500 —— ✅ 已修复（2026-09-15 晚）

**现象（修复前，生产实测）**：
```bash
curl -s -o /dev/null -w "%{http_code}" https://learn.yuanabd.cn/api/habits        # → 500
curl -s -o /dev/null -w "%{http_code}" -H "Authorization: Bearer x" …/api/habits  # → 200（哪怕 token 无效）
curl -s -o /dev/null -w "%{http_code}" -H "Authorization: Bearer " …/api/habits   # → 500（空 Bearer）
```
同样 500：`/api/certificates`、`/api/nutrition`、`/api/nutrition/summary`、`/api/workouts`、`/api/trackers`；
`/api/daily`、`/api/nutrition/target`、`/api/wellbeing/weight|hydration`、`/api/nutrition/foods` 正常 200。
日志：`TypeError: The "data" argument must be of type string or an instance of Buffer… Received null`
（`code: ERR_INVALID_ARG_TYPE`，来自会话哈希工具）。

**根因**：这些路由都走 `userScope()` → `currentUserId()`，而匿名请求的 token 为 `null`
（空 Bearer 会被 `slice(7).trim()` 归一化成 `""`），随后 `hashToken(token)` 执行
`createHash("sha256").update(null)` → 抛 `ERR_INVALID_ARG_TYPE` → Next 返回 500。
`/api/daily` 之所以正常，是因为它按踩坑点 34 的写法先取 token、再决定要不要查会话。

**修复（三层防护，任一层都能挡住 500）**：
1. `lib/anon.ts` 的 `userScope()`：**try/catch 兜底**，会话解析任何失败都降级为匿名作用域
   （只读接口返回空集合，写接口走匿名隔离），绝不把异常抛成 500；
2. `lib/session.ts` 的 `hashToken()`：空值归一化为空串（空串哈希查不到任何会话 == 未登录，且不抛错）；
3. `destroySession()` 增加空 token 短路（避免误删与空哈希）。

**回归测试（关键：这类 bug 靠原有 route 测试抓不到 —— 它们全都 mock 了 `userScope`）**：
- 新增 `apps/web/lib/anon.test.ts`（8 条）：无 cookie/无 Authorization、空 Bearer、只有匿名 cookie、
  取 token 抛错、正常会话各路径；
- 新增 `apps/web/app/api/nutrition/summary/anonymous.test.ts`（2 条）：**不 mock anon/session**，
  走真实 `userScope()`，断言匿名请求返回 200 空汇总且不查会话表。

**修复后验证（生产重新部署后实测）**：无头 / 匿名 cookie / 空 Bearer / 无效 Bearer → **全部 200**；
`/api/nutrition/summary?days=3` 返回三天全 0（`generate_series` 补齐正常）、`/api/nutrition?date=` 空集合、
`/api/habits` 空集合；带 Bearer 路径与 `/login` 均 200；新容器日志中该类错误 **0 条**（修复前 7 条）。

> 无需重新出包：这是纯服务端修复，v1.3.2 APK 直接受益（未登录用户不再看到加载失败）。

72. **RN `Modal` 内的手势必须再包一层 `GestureHandlerRootView`（2026-09-17 真机反馈的根因）**：Android 的 Modal 是**独立 Window**，app 壳层那个根视图收不到它的触摸流 → Modal 内的 `Gesture.Pan/Pinch` **静默失效**（不报错、只是不动）。本次表现为 LiveLog 贴纸"只能点不能拖、位置永远在初始槽位"。修法：`BottomSheet` 的 Modal 内容根节点换成 `GestureHandlerRootView`（保持 `flex:1`），一处修全部 30 个弹层。注意副作用：`BottomSheet` 自带的下滑关闭手势在 Android 上也会随之真正生效。
73. **`GlassSurface` 的"看穿"来自实底色之上的 alpha tint 覆盖层（2026-09-17）**：Android 回落分支先给 `styles.elevated`（不透明 `surfaceStrong`），随后又叠 `glassTintOverlay`（`rgba(255,255,255,0.86)` / `rgba(20,24,28,0.72)`）→ 最终半透明。要"完全不透"就必须**跳过这一层**（本次给 `GlassSurface` 加 `opaque`，并且 opaque 时**两个平台都走实底分支** —— iOS 的 `GlassView` 是系统玻璃，`tintColor` 只染色不保证不透光）。
74. **键盘避让要做"自校正"，不能假设窗口是否已 resize（2026-09-17）**：Android 的 Modal（Dialog）被 RN 设了 `ADJUST_RESIZE`，键盘弹出时**窗口自己就变矮**；iOS 全屏 Modal 窗口不变。所以"该补多少"取决于窗口是否已经把键盘高度吃掉：只按 `kb` 上抬 → Android 双重补偿（顶边被裁）、iOS 正确；只按窗口变矮 → 视觉"往下缩"（v1.4.0 反馈）。本次方案：高度基准用 `screen - insets.top - insets.bottom`（对键盘免疫）并**随键盘收缩**；上抬量 = `max(0, kb - (screen - 实测根容器高度))`。**顺带**：`useAnimatedStyle` 的 worklet 会在定义处快照自由变量，所有参与计算的局部量必须声明在它之前（踩坑 71）。
75. **"点空白关不掉"往往是状态机而不是手势问题（2026-09-17）**：训练记录里弹层"关掉又自己弹回"，根因是"选择动作"弹层的退场回调**无条件**把记录弹层重新打开（`onPickerClosed → setSheetOpen(true)`）。修法：引入"意图"标记（只有用户**确认选择**才回主弹层），并在所有关闭出口无条件清零 pending/意图 —— **不要**用 `setTimeout` 兜。
76. **`apksigner` 在 PowerShell 管道里会等 stdin 而挂死（2026-09-17 连踩两次）**：out 表现是 gradle 早已 `BUILD SUCCESSFUL`，`build-android-release.ps1` 却卡在"校验签名"十几分钟不结束（`[exit code: 1]` 只在被工具超时杀掉后才出现）。**修法**：调用处加 stdin 重定向 —— `& cmd /c "`"$apksigner`" verify --print-certs `"$apk`" < nul 2>&1"`（已固化进脚本并加注释）。若再次遇到卡死，也可按踩坑 53 直接从 `android/app/build/outputs/apk/release/app-release.apk` 手动核验签名并拷进 `.local/accept/`。
77. **"选择即开始"是很危险的默认交互（2026-09-17 真机反馈）**：一键开始弹层原来"点任意选项立即开始计时"，于是**想退出的人**一旦碰到选项就被送进计时（用户从侧滑返回/点空白想退出，结果直接开始学习）。**规则**：弹层内的点选只改**选择态**，启动必须是**唯一的显式按钮**（本项目为底部「开始计时 · <当前选择>」），并且所有关闭路径（侧滑返回 / 点空白 / 返回键）只做关闭；父级用"待启动选择"这个状态位配合 `onClosed` 串行，**没有点开始按钮就绝不启动**（打开弹层时顺手清空该状态位作为兜底）。
78. **worklet 在定义处快照自由变量 —— 顺序错了会直接闪退（2026-09-18 真机崩溃根因）**：`bottom-sheet.tsx` 的 `panGesture.onEnd` 读了 `lift.value`，而 `lift`（`useDerivedValue`）声明在手势**之后** → worklet 里拿到 `undefined` → UI 线程 TypeError → Android 直接退出（表现：点/拖抽屉顶部横线就闪退）。这是踩坑 71 的**致命版**（71 是静默 NaN，这里是崩溃）。**规则**：所有被手势/`useAnimatedStyle` 读取的量必须声明在它们之前；改 `bottom-sheet.tsx` 时先看文件里的「⚠️ 顺序约束」注释。顺带发现：`expandable` 从未被任何调用方启用 → 「拖到全屏」这个功能其实不存在（v6 决策 D12）。
79. **UI 线程 worklet 里同步调用普通函数 = 闪退（2026-09-18）**：`portion-slider.tsx` 的 `onEnd` 调用 `lib/portion.ts` 的 `snapPortion()`（普通函数）→ `Tried to synchronously call a non-worklet function on the UI thread` → 崩。之所以 v1.4.2 才暴露：v1.4.1 之前 Modal 内手势根本收不到触摸（踩坑 72），这段 worklet 从没真正执行过。**修法（双保险）**：① 纯函数加 `"worklet"` 指令；② 吸附/回弹/回调搬到 `runOnJS`（UI 线程只读共享值）。**规则**：worklet 里只允许「共享值读写 + runOnJS + Reanimated API」。
80. **乐观入账会被随后的 `load()` 覆盖（2026-09-18 真机「提示成功但页面没有、数据仍 0」）**：`nutrition.tsx` 的 `addManual()` 在离线/5xx/401 分支先 `setEntries` 乐观入账，却在函数末尾**无条件** `await load()`；服务端列表里没有这条 → 直接覆盖。对照 `quickAdd()` 离线分支在 `load()` 前 `return`，所以「鸡蛋能显示、手动添加不能」。**修法**：① 只有真正落库成功才 `load()`；② `load()` 一律用 `mergePendingEntries(server, outbox)` 合并待同步条目；③ 顶部加「N 条待同步 · 点此重试」状态条。以后写任何「乐观 UI + 后台补发」都按这三条来。
81. **pg_trgm 对纯中文不生成 trigram（2026-09-18 实测，v6 食物库踩到）**：`show_trgm('番茄鸡蛋面')` 返回 `{}`、`similarity()` 恒为 0 —— pg_trgm 只把**字母数字**当词字符，中文短串既不进索引也不参与相似度。后果：用 `similarity(name, q) > 0.25` 做「错别字容错」在中文上完全是空转（`鸡旦` 搜不到 `鸡蛋`），而 route 测试全是 mock，不会发现。**修法**：`GET /api/foods/search` 改用**字符覆盖率**评分 —— `(SELECT count(DISTINCT ch) FROM unnest(regexp_split_to_array(lower(name), '')) ch WHERE ch IN (SELECT unnest(regexp_split_to_array(lower($2), '')))) / GREATEST(length($2), 1)`，阈值 ≥ 0.5，并保留子串命中（名称/英文名/拼音/别名）优先。**规则**：凡是要在 Postgres 里做**中文**模糊匹配的，先用 `SELECT show_trgm('中文串')` 验证一句话，再决定用 trgm 还是字符覆盖率/自定义算法；本地库（`scripts/start_pg.ps1`）可以直接验，不要只靠 mock 测试。
82. **`db/schema.sql` 会与迁移链漂移，「全新库初始化」因此失败（2026-09-18 实测并修复）**：docker init 对**全新库**执行 `db/schema.sql`，但该文件是人工维护的完整 schema，随迁移追加容易漏列/错序。实测两处：① `content_phases` 定义在 `users` **之前**却 `owner_id uuid REFERENCES users(id)` → 该语句失败并连带后面所有内容表级联失败；② `focus_sessions` 少了迁移补的 `client_id / anon_id / focus_minutes_applied / deleted_at / updated_at`，执行到 `uq_focus_sessions_client_anon` 时 `column "anon_id" does not exist`。**已修**：`users` 提到文件最前 + `focus_sessions` 补 5 列。**规则**：改 `schema.sql`、或新增「加列/建表」的迁移后，跑一次 **`node scripts/check-schema-fresh.mjs`**（在空库上执行 schema.sql + 全部迁移，逐语句报错；需本地 PG 或 `PG*` 环境变量）——生产只跑增量迁移，这类问题**不会**在生产暴露，只会在新环境/灾备重建时集中爆发。

83. **`react-hooks/set-state-in-effect`（React 19.2 / eslint-plugin-react-hooks 新规则，2026-09-18 v9 踩到）**：在 effect 体内**同步** `setState` 会被判 error——最典型的触发点是「进入空结果分支先清列表」（`setItems([])` / `setDbItems([])`），以及把「清理」写在 effect 开头的写法。**修法**：把清理动作移进 `setTimeout(…, 0)`（或改成事件/派生状态驱动），**不要**用 `// eslint-disable` 掩盖。**规则**：写「搜索/加载」类 effect 时，effect 体内只做「取数据 → setState(结果)」，清空/重置一律走异步 tick 或调用方。

85. **本地 `tar czf --exclude=…` 打包会失手：Windows 的 bsdtar 是按「整条路径」匹配排除项（2026-09-19 部署 v10 踩到）**：
`tar czf out.tgz --exclude=.pgdata … .` 里 `.pgdata` 并不匹配 `./.pgdata/base/…`，于是 91MB 的数据库目录被打进包，本地报 `tar.exe: (null)`、远端 `gzip: stdin: unexpected end of file / Unexpected EOF in archive`（上传的其实是截断文件，95MB）。

86. **expo-router 的 `<Tabs>` 会把 `app/` 下「所有」路由自动注册成 Tab（2026-09-19 真机发现第 6 个 Tab）**：`app/_layout.tsx` 只显式声明了 5 个一级 Tab，但 expo-router 会为**每个**路由生成 Tab，除非用 `<Tabs.Screen name="X" options={{ href: null }} />` 显式隐藏。v1.9.0 新增 `sports-card.tsx` 时漏了这行 → 底部导航多出一个空标题 Tab（排在「我的」右边），用户一眼看到。**规则**：在 `app/` 下新增任何页面后，必须去 `_layout.tsx` 的「次级页面：不占底部导航」区块补一行 `href: null`；真机验收第一步就是**数 Tab 个数**。
