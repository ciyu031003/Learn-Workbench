# 学习工作台下一个大版本的具体改动方向和设计方案

> **项目：Learn-Workbench**
>
> **版本定位：下一代大版本 / Learn-Workbench 2.0**
>
> **核心策略：先重构 UI/UX 与信息架构，再新增功能，最后完善数据能力与智能能力。**
>
> 本文用于作为下一版本的产品、UI/UX、功能和工程实施路线，建议按照阶段逐步落地，而不是一次性进行大规模重构。

---

## 一、版本总体定位

Learn-Workbench 当前已经从单纯的学习记录工具逐渐发展为一个包含：

- 学习路线
- 每日任务
- 专注
- 学习日志
- 项目
- GitHub
- 职业路线
- 健康提醒
- 招聘信息采集

等能力的个人成长工作台。

加入招聘信息采集后，项目最重要的变化不是“增加了一个招聘页面”，而是产品开始具备：

> **学习 → 技能 → 项目 → 招聘 → 求职 → 职业成长**

这一完整闭环。

因此，下一个大版本不建议继续单纯堆叠功能，而应该围绕“职业成长工作台”重新梳理产品结构。

### 2.0 的核心目标

```text
学习工作台
    ↓
个人成长工作台
    ↓
职业成长工作台
    ↓
Career OS
```

最终形成：

```text
我应该学什么
      ↓
我正在学习什么
      ↓
我已经掌握什么
      ↓
市场需要什么
      ↓
我还缺什么
      ↓
我应该投什么岗位
      ↓
我如何准备求职
      ↓
我最终获得什么职业结果
```

# 二、下一版本总体实施原则

## 2.1 第一原则：先 UI，后功能

本版本必须严格按照：

```text
UI / UX
   ↓
信息架构
   ↓
核心流程
   ↓
功能新增
   ↓
数据能力
   ↓
智能能力
```

进行。

不要在旧 UI 上不断增加新功能，否则最终容易出现：

- 导航越来越复杂
- 页面越来越拥挤
- 功能之间互相割裂
- 移动端体验下降
- Web 端信息密度失控
- 视觉风格不统一

---

# 三、2.0 产品核心定位

## 3.1 不再只是“学习工作台”

新的产品定位建议定义为：

> **面向个人学习与职业成长的一体化工作台。**

核心不是“招聘”，也不是“学习”。

真正的核心是：

> **帮助用户完成从学习到职业发展的完整闭环。**

## 4.1 健康功能不建议作为一级导航

健康提醒应该作为系统级能力存在：

- 久坐提醒
- 喝水提醒
- 休息提醒
- 工作时长提醒

而不是占据一个独立一级导航。

例如：

> 💧 已连续工作 55 分钟，建议补充水分。

> 🧍 已连续坐姿 60 分钟，建议起来活动一下。

# 五、UI 重设计总体方向

## 5.1 保留 Liquid Glass

不建议推翻目前的 Liquid Glass 视觉体系。

它已经成为 Learn-Workbench 的明显视觉识别特征。

但是需要从：

> “所有元素都玻璃化”

升级为：

> **Liquid Glass 2.0**

核心原则：

> **背景负责氛围，玻璃负责层级，内容负责信息。**

---

# 六、Liquid Glass 2.0 设计原则

## 6.1 背景层

负责：

- 氛围
- 品牌感
- 沉浸感

可以使用：

- 风景背景
- 渐变
- 环境光
- 柔和光斑
- 模糊

但背景不能影响阅读。

---

## 6.2 内容层

负责：

- 信息
- 数据
- 操作
- 状态

内容应该使用更高对比度。

---

## 6.3 玻璃层

玻璃只承担：

- 卡片层级
- 内容分组
- 浮层
- 导航
- 重点模块

不要让所有按钮、标签、列表都使用强玻璃效果。

---

# 七、不同页面采用不同视觉密度

这是 2.0 UI 非常重要的设计原则。

| 页面 | 视觉方向 |
|---|---|
| 首页 | 沉浸式、视觉优先 |
| 学习 | 效率型、任务优先 |
| 招花 | 信息密度型 |
| 职业 | 数据型、结构化 |
| 市场分析 | 专业数据型 |
| 设置 | 简洁、低视觉干扰 |

不能所有页面都使用完全相同的卡片密度。

# 二十二、职位数据标准化

不同来源的数据必须统一。

例如：

```text
15-25K
15000-25000
20K左右
```

统一为：

```json
{
  "salary_min": 15000,
  "salary_max": 25000,
  "salary_period": "month"
}
```

还应该统一：

- 城市
- 工作经验
- 学历
- 职位名称
- 公司名称
- 技能标签
- 发布时间
- 数据来源

# 二十七、Web 与移动端设计差异

| 能力 | Web | Mobile |
|---|---|---|
| 信息密度 | 高 | 低 |
| 筛选 | 侧边栏 | Bottom Sheet |
| 职位详情 | 右侧面板 | 独立页面 |
| 数据分析 | 强 | 精简 |
| 操作 | 鼠标 + 键盘 | 触控 |
| 导航 | 顶部/侧边 | Bottom Tab |
| 多任务 | 强 | 弱 |

原则：

> **同一设计语言，不同交互方式。**

# 二十九、动效设计

不要为了炫技添加大量动画。

推荐：

### 微交互

- Hover
- Press
- Focus
- Card transition
- Modal transition

### 页面切换

保持轻量：

```text
150ms - 300ms
```

### 数据变化

使用：

- Count animation
- Progress animation
- Skeleton
- Fade

不要出现长时间的页面动画。

# 三十九、当前阶段明确“不做什么”

- 不要大量增加新的一级导航
- 不要重复建设已有功能
- 不要为了 AI 而 AI
- 不要把所有页面做成玻璃卡片
- 不要直接复制传统招聘网站 UI
- 不要同时重写所有后端模块
- 不要在 UI 尚未稳定时大量开发新功能
- 不要为了功能数量牺牲信息架构
- 不要为了视觉效果牺牲性能

# 四十一、最终设计理念

Learn-Workbench 2.0 不应该成为：

> “学习工具 + 招聘爬虫 + 简历工具 + AI 工具的功能集合”。

而应该成为：

> **一个围绕个人职业成长建立的数据化工作台。**

最终核心闭环：

```text
                我的职业目标
                     ↓
                我的技能画像
                     ↓
             ┌───────┴───────┐
             ↓               ↓
           学习              市场
             ↓               ↓
           项目          招聘需求
             ↓               ↓
           GitHub        岗位匹配
             └───────┬───────┘
                     ↓
                  能力缺口
                     ↓
                  学习计划
                     ↓
                  求职准备
                     ↓
                  投递 / 面试
                     ↓
                    Offer
```

这才是 Learn-Workbench 下一阶段真正值得做的产品闭环。

# 四十二、结论

当前项目已经具备继续升级的基础。

下一版本最重要的事情不是继续增加功能，而是：

> **先把产品“重新组织起来”。**

第一阶段：

> **UI / UX 重构**

第二阶段：

> **招花招聘系统完善**

第三阶段：

> **学习与招聘数据打通**

第四阶段：

> **求职管理**

第五阶段：

> **招聘市场分析**

第六阶段：

> **AI 智能化**

其中最重要的一条原则：

> **先建立体验，再建立功能；先建立数据关系，再建立 AI。**

如果按照这条路线推进，Learn-Workbench 可以从一个功能丰富的个人学习工具，逐渐升级为一个真正有产品特色的：

# **Personal Career OS / 个人职业成长操作系统**
