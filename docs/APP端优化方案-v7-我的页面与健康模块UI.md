## 2. 「我的」页面重构

### 2.1 现状（`apps/mobile/src/app/settings.tsx`，568 行）

- Hero（我的 / 账号 · 学习领域 · 数据同步）→ 一张**巨型 Card 装了账号 + 同步按钮 + 提示文案 + 账号与安全行**（L213-293）；
- 「进阶设置」折叠卡（领域管理 / 本机数据，L295-355）；
- 之后是 `Card title=...` 平铺：外观 / 每日背景图 / 手势 / 关于（L359-440）；
- `ListGroup/ListRow` 只用了 1 处（账号与安全）——组件已就绪但没用起来，这正是「粗糙感」的来源：**同一屏里混用了 3 种卡片语言**（hero 卡、折叠卡、title/subtitle 卡）。

### 2.3 视觉规范（全部用现有 token）

| 元素 | 规范 |
| --- | --- |
| 分组标题 | `typography.micro` + 700 + `colors.textMuted`，上下间距 20/8 |
| 组容器 | `ListGroup`（radius.lg、hairline border、`surfaceStrong`、overflow hidden） |
| 行 | 高 ≥56、左右 14、图标槽 36×36（radius 11）、主文字 15·600、副文字 12·muted、右值 13·muted、chevron 16·textFaint |
| 语义色 | 账号=primary(蓝)、学习=紫(#8D7BD8)、习惯=accent(橙)、数据=青(#2FB3A6)、成功=绿、隐私/关于=textMuted；**淡底 = 颜色 + 22 alpha**（现有 `colors.primarySoft` 同款做法） |
| 交互 | `PressableScale scale 0.98` + `haptics.light`；开关行整行可点（点行=切开关，符合截图习惯） |
| 无障碍 | `accessibilityRole="button"`、开关用 `role="switch"` + `accessibilityState`、点击区 ≥44 |
| 头图 | 头像 56 圆 + 昵称 17·700 + 一行同步状态（复用现有 `sync-engine` 状态文案） |

### 2.4 拆分与文件级改动

- `app/settings.tsx`：**只做编排**（重建信息架构，删除三种混用的卡片写法），预计从 568 行降到 ~380 行；
- 新组件 `components/group-label.tsx`（10 行）+ 语义色映射放 `theme/tokens.ts`（`semanticColors(colors)` 纯函数，便于两端统一）；
- 「关于」组：把版本号 / 备案 / 隐私政策 / THIRD_PARTY 链接集中（现在分散在 Card + ota 逻辑里）；
- 保留所有既有能力（登录/退出、同步/恢复、主题切换、背景开关、手势开关、检查更新、重置数据），**只改外表与分组**，不改业务逻辑；
- 「进阶设置」折叠卡取消：领域管理 / 领域记录 / 导出导入 上移到对应分组（截图范式里没有折叠卡）。

## 3. 健康模块 UI 优化

### 3.1 现状

`app/wellness.tsx`（Hub）：hero 今日状态分（readiness 进度弧）+ 饮食摘要卡 + 4 宫格入口（饮食/训练/习惯/领域记录）+ 单条「快速记录」；
`app/nutrition.tsx`（1675 行，最重）、`app/workout.tsx`、`app/habits.tsx`、`app/trackers.tsx` + 组件 `water-card / weight-card / progress-arc / macro-mini-rings / calorie-trend / food-calendar / water-cup / nutrition-stats-sheet / charts`。
问题：**层级平**（hero 与 4 宫格都是「一张卡」）、**入口多于内容**（用户每天关心的是「还剩多少可吃 / 今天喝了几杯 / 体重趋势」而非 4 个入口）、趋势信息藏在二级 Sheet 里。

### 3.2 目标：三层结构

**① 今日状态（Hero，1 张）**
- 保留 readiness 进度弧 + 分数，但把四项分解改成**横条微图**（任务 40 / 习惯 30 / 训练 15 / 饮食 15），点横条直达对应模块；
- 右上角加「今日建议」一行（复用现有 `lib/readiness.ts` 的最短板提示）。

**② 今日动作（4 张可交互卡，替换现在的入口宫格）**
| 卡 | 主数值（大字 tabular-nums） | 交互 |
| --- | --- | --- |
| 饮食 | 「还能吃 620 kcal」+ 三微环 | 点「记一条」→ 营养库搜索（v6 已做） |
| 饮水 | 「1200 / 2000 ml」+ 玻璃杯液面动画 | +200/300/500 一点即记、撤销（已有 `water-card`） |
| 训练 | 「本周 3 次 · 142 分钟」 | 点「记录训练」→ 动作库大卡片（v6 已做） |
| 体重 | 最新值 + 7 日均线 + ±变化徽章 | 点 + → 记录体重（已有自研弹层） |

**③ 趋势与档案（折叠区/二级页）**
- 7 天热量曲线、6 个月点阵日历（已有 `calorie-trend` / `food-calendar`）、目标设置（`TargetSheet`）、运动档案与分享；
- 统一从「趋势」入口进入，避免首屏堆图。

### 3.3 视觉与手感规范

- 语义色固定：能量=橙 `accent`、达标=绿 `success`、饮水=青 `#2FB3A6`、体重=紫 `#8D7BD8`（v3 已定，沿用）；
- 大数字：斜体 + tabular-nums + 单位小字（现有 `AnimatedNumber` 已支持）；
- 卡片：radius 20、内边距 16、卡间距 12、组内行距 8；只有 Hero 与状态卡用玻璃（v2 §D2 决策不变）；
- 动效克制：数值 beat（已有）、液面缓动 300ms、进度弧 spring；**不做**粒子/3D/视差（v3 §D9 决策不变）；
- 每个卡片都能「点进去」，禁止出现「只能看不能动」的装饰卡。

### 3.4 组件级改动清单

| 组件 | 改动 |
| --- | --- |
| `wellness.tsx` | 重排为三层；删掉 4 宫格入口卡；Hero 加四项分解横条 + 最短板提示 |
| `water-card.tsx` / `water-cup.tsx` | 液面缓动 + 目标达成脉冲（一次，不循环）；`+200/300/500` 改为药丸按钮行 |
| `weight-card.tsx` | 趋势线加 7 日均线虚影 + 「较上周 ±0.3kg」徽章（红/绿语义） |
| `nutrition.tsx` Hero | 剩余额度大数字 + ProgressArc 渐变描边（现有 `beatOnChange` 保留） |
| `macro-mini-rings.tsx` | 统一线宽 6、间距 10、区间达标用绿点标记 |
| 新增 `week-overview.tsx` | 「本周概览」一条：运动 N 分钟 · 达标 N 天 · 平均 N kcal（一次请求 `/api/daily` 或复用现有聚合） |

## 4. three.js / 3D 评估（点名项，结论：App 端不做）

**官方证据**：`@react-three/native`（R3F 的 RN 绑定，仓库 `pmndrs/native`）README 原文：

> “With SIGNIFICANT performance issues with ExpoGL most of us internally are pretty anti-React-Native. … Right now its raw, pre alpha and unusable.”
> —— https://github.com/pmndrs/native

也就是说：RN 上的 three.js 走 `expo-gl`（WebGL）通道，官方自己承认性能问题严重、native 支持不成熟。叠加我们的实际约束：

1. **包体**：three.js + expo-gl + R3F 约 +2–4MB（当前 APK 66.9MB，已经不小），且需要一次原生构建；
2. **性能与发热**：中低端安卓（我们的主要用户群，含 OPPO/ColorOS 机型）在 60fps 3D 下掉帧、发热，与「记录型 App 要快、要稳」的目标冲突；
3. **收益**：健康模块的信息是数值型（kcal/克数/ml/kg），3D 只能提供「炫」的观感，不提升记录效率；
4. **可维护性**：`gesture-handler + reanimated 4 + worklets` 已经踩过两次真机崩溃（v6 踩坑 78/79），再引入 WebGL 线程会显著扩大崩溃面。

**替代路线（按推荐顺序）**

| 方案 | 成本 | 能做什么 | 建议 |
| --- | --- | --- | --- |
| 现有 `react-native-svg + reanimated` | **0 依赖** | 环/弧/液面/热力图/曲线（现已在用） | **首选**：本方案 §3 全部可用它实现 |
| `@shopify/react-native-skia` | +1 依赖（约 2–3MB，需原生构建；RN 0.86 / Expo 57 支持） | 高性能渐变、模糊、粒子、流体液面、真实曲线（图表质感明显提升） | 若你要「明显更高级的质感」→ 先做 **单个组件试点**（水杯液面 + 体重曲线），真机验收后再推广 |
| `expo-gl` + three.js（非 R3F 最小用法） | +2–4MB + WebGL 线程 | 真 3D（如 3D 水杯/体成分球） | **仅限**低频、可延迟加载的页面（分享卡/年度报告），FeatureFlag + 降级到静态图 |
| Web 端 three.js / CSS 3D | 0（不进 App 包体） | 落地页 / 分享页的 3D 展示 | 想做 3D 观感时**优先放在 Web** |
