## 1. Web 端：呼吸的色彩 / 炫彩灯效（克制版）

**设计原则**：光只出现在"值得被注意的地方"（进度、打卡、主 CTA、每日一言），不超过 3 处/屏；全部走合成器属性（transform/opacity/局部 box-shadow）；沿用项目惯例尊重 `prefers-reduced-motion`。

### 1.1 氛围底光（问候卡 + 页面顶部）
- 在 Hero 问候卡背后放 2 个预模糊的 `radial-gradient` 柔光色块（不要用 `filter: blur()` 动画——大面积 blur 动画是性能杀手），以 10~14s 周期缓慢漂移 + 透明度呼吸。
- 颜色按时段变化形成"一天的心情"：晨（杏金 #FFD9A0 + 天蓝 #BBD7F5）、午（蓝 #A8CBF0 + 青 #A5E3D8）、暮（橙 #FFB46E + 紫 #C9B8F0）。
- 深色模式下光感加强（透明度 0.08 → 0.16），夜间"灯"的意象更成立。
- 落点：`globals.css` 新增 `--glow-*` 令牌 + `@keyframes breath-drift`；`daily-background`（Web 版）与 dashboard Hero 组件。

### 1.2 数据卡的"生命感"
- 整体进度环（右上 0%）：锥形渐变描边 + 光晕脉冲（`box-shadow` 0 0 24px 单色 8% 透明度，2.6s ease-in-out）。
- 连续打卡的 🔥 换成 SVG 火苗 + glow 呼吸，且**火光强度随连续天数递进**（1/3/7/21 天四档：微光→暖光→亮光→辉光），把灯效做成游戏化叙事的载体。
- 卡片 hover：彩色 ring-glow（`box-shadow: 0 0 0 1px rgba(primary,0.25), 0 12px 32px -16px 三色混合`），位移 2px 上浮。

### 1.3 渐变描边（只给 1~2 张重点卡）
- "每日一言"与"今日打卡"卡用 1px conic-gradient 旋转描边（`@property --angle` 动画，Firefox 降级为静态双色渐变描边）。这是"炫彩灯效"里最接近霓虹的元素，务必限量。

### 1.4 主 CTA 呼吸
- "今日打卡"按钮 idle 状态 2.6s 呼吸阴影（sun→coral 双色），hover/focus 停止呼吸并提亮——按钮像在轻轻"呼气"邀请点击。
- "一键学习/一键运动" hover 时图标色块泛起对应主题色 glow。

### 1.5 微灯效点缀
- 招花列表 `NEW` 徽章：6s 周期一次的 shimmer 扫光（伪元素平移 + 渐变遮罩）。
- 图表（market-charts）数据热点：最新数据点加脉冲光圈。

## 2. 移动端精致化（对标 Apple HIG）

### 2.1 基础体验层（性价比最高，先做）
1. **触感**：安装 `expo-haptics`，封装 `HapticsService`（light/soft/success/warning/notify），替换 `Vibration.vibrate(8)`。打卡成功 `.success`、完成任务 `.light`、删除 `.warning`——这是"苹果手感"的第一要素。
2. **SF Symbols**：Tab 栏与核心卡片图标逐步换 `expo-symbols`（perspective/graduationcap/flame/checkmark.seal 等语义图标），Android 降级 Ionicons；已装的 `expo-symbols` 直接可用。
3. **暗色模式（P1 最大缺口）**：`tokens.ts` 增加 Dark 档（建议"苦旅·夜航"：#0F1420 底、暖橙强调、玻璃层提亮），跟随系统 + 设置内三档（浅色/深色/跟随系统，与 Web 对齐）；`DailyBackground` 出暗色 blob 变体；每日壁纸模式按图片亮度自动切 status bar 风格。

### 2.2 导航与转场
- **重做 SwipeNavigator**：现在是全屏透明覆盖层截横滑（zIndex 60），会吃掉子页横向手势、与 learn sheet 手势抢事件。改为每屏内嵌 pan 手势 + reanimated 驱动的跟手转场（进度联动位移/视差），或至少把 gesture 域收敛到屏幕边缘。
- Tab 切换加微转场：内容 `translateY 8 + fade 180ms`；浮岛 TabBar 选中项从"背景色块"升级为弹性位移指示器（spring）+ 图标 spring 弹跳（招花花朵图标已有此效果，推广到全部 tab）。
- 首页 Hero 做 iOS 大标题联动：滚动时大标题缩为行内导航标题（`useAnimatedScrollHandler` 插值）。

### 2.3 组件级
- **列表 inset grouped 规范**：设置/我的页按 iOS 分组样式统一——组头 13px 大写次要色、行高 44pt、右侧 chevron、组脚注说明（现在 Card 已接近，差细节规范）。
- **长按 Context Menu**：任务/职位卡长按弹出预览 + 快捷操作（完成/删除/收藏），配 `.medium` 触感。
- **数字滚动动画**：统计卡数字用 spring 滚动（0→当前值），打卡/进度环填充与 celebration、触感联动。
- **骨架屏统一**：各页加载态统一 Skeleton 组件（现在多为空白跳动）。

### 2.4 页面针对性
- **登录/注册独立成 modal sheet**（玻璃卡、spring 关闭、错误 shake 动画、密码可见切换、即时校验）；首启未登录给 onboarding 引导 + "先逛逛"游客模式（离线优先本来就是卖点，要把"不登录也能用"讲清楚）。
- **"我的"页拆分**：现在一屏塞了账号表单+修改密码+领域切换+壁纸开关+数据重置+关于。拆为 iOS 风格分组：`账号与安全`（头像昵称、微信绑定、修改密码、注销）/`偏好`（领域、壁纸、触感开关）/`数据`（同步状态胶囊化）/`关于`。
- 首页"开始专注"CTA 移入拇指区（底部悬浮主按钮或快捷卡第一张）。

## 3. 账号体系重构 + 微信绑定

### 3.1 数据模型（`db/migrations/` 追加，不改历史）
```sql
CREATE TABLE identities (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  provider text NOT NULL,              -- 'password' | 'wechat'
  provider_uid text NOT NULL,          -- wechat: openid
  unionid text,
  nickname text,
  avatar_url text,
  meta jsonb NOT NULL DEFAULT '{}',
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (provider, provider_uid)
);
CREATE INDEX idx_identities_user ON identities(user_id);
```
现有账号密码数据不动（password 作为一条 identity 或维持 accounts 表，推荐逐步并入 identities 统一模型）。`users` 补 `nickname/avatar_url` 可选列。

### 3.2 后端 API（每个 route 配套 route.test.ts，项目铁律）
- `POST /api/auth/wechat/app/session`：App 端 SDK 拉起微信授权拿到 `code` 回传 → 服务端调微信接口换 `openid/unionid` → 命中 identity 直接 `createSession` 返回 Bearer；未命中且请求声明"合并本机数据"则建新用户 + 绑定 + 走既有匿名数据迁移路径。
- `POST /api/auth/wechat/bind` / `DELETE /api/auth/wechat/bind`：登录态绑定/解绑（解绑需保留至少一种登录方式）。
- Web 扫码（网站应用）：`GET /api/auth/wechat/qrcode` 生成带 `state` 的授权链接 + `GET /api/auth/wechat/callback` 处理回调，前端轮询/SSE 感知登录成功。
- 安全线：`state` 防 CSRF、`code` 一次性且短时效、AppSecret 只存服务端 env、openid 按 appid 隔离、unionid 做多端打通。

### 3.3 客户端
- Web `/login`：登录卡加"微信扫码"入口（二维码 + 过期自动刷新），扫码成功跳 dashboard。
- App：选型两库之一——`react-native-wechat-lib`（de facto，但维护弱：npm latest 停在 1.1.26，代码 3.0.x beta）或 `hector-zhuang/native-wechat`（TurboModule，更贴合 RN 0.86 新架构，建议优先试这个）。流程：`registerApp(appid)` → `sendAuthRequest` → deep link 回调（`expo-linking` 已装）。Android 包名 `com.yuanabd.learnworkbench` + 应用签名 MD5 需登记到开放平台。
- **Token 存储升级**：`expo-secure-store` 保存 token（现为 AsyncStorage 明文）。
- "我的→账号与安全"：微信绑定行（头像昵称/绑定/解绑）、注销账号入口（上架合规必需）。

### 3.4 前置依赖与合规（需要你先决策/办理）
1. **微信开放平台资质**：网站应用与移动应用需分别创建，且通常要开发者资质认证（个人主体受限，企业主体常规）。**未拿到 appid 前，代码按 mock provider 先行开发，不阻塞**。
2. 域名已备案（learn.yuanabd.cn）满足网站应用要求；App 后续上架需要 App 备案 + 可访问的隐私政策页。
3. 忘记密码：短信成本高，建议先做邮箱重置（重置 token 表 + Resend/SMTP 发信），同时移除"联系管理员重置"文案；Web 登录页补"注册"入口（移动端已有接口）。
