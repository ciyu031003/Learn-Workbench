# ADR-002：数据工程严谨性（审计列 / 乐观锁 / 外键索引 / 可回滚迁移）

- **状态**：已采纳
- **日期**：2026-10-11
- **阶段**：组三 · 阶段 15（V3 横轨 H1）
- **相关文件**：`db/migrations/064_h1_data_hardening.sql`、`db/migrations/down/064_h1_data_hardening.down.sql`、
  `db/schema.sql`、`scripts/db-index-inventory.mjs`、`scripts/migration-drill.mjs`、
  `content-platform/db/index-inventory.md`

## 1. 背景（实测依据）

在 `check-schema-fresh` 造出的**全量库**上直接用 `pg_catalog` 体检（不是靠读文档猜）：

- `pg_constraint` 里 **13 条外键没有支撑索引**（引用列上的 `DELETE/UPDATE` 会全表扫、`JOIN` 退化成 seq scan）；
- 运营可编辑的内容表（`content_phases` / `content_topics` / `knowledge_points` / `content_source`）
  **没有审计列**（不知道"谁改的"），**没有乐观锁**（并发覆盖只能靠事后发现）；
- 迁移只有正向脚本，**没有可执行的回滚契约**：`db/migrations/` 里 63 个文件全是 up，
  回滚只能人肉回忆改过什么，无法验证"可回滚"。

## 2. 决策

1. **只给"有运营编辑入口"的表补审计列与乐观锁**：无人工编辑入口的学习者数据表（`learning_attempts`、
   `habits` 等）不加 `created_by`/`updated_by`，避免为了"齐整"给 90 张表加永远为空的列。
2. **乐观锁用整型 `version`**（`int NOT NULL DEFAULT 1`）+ `CHECK (version > 0)`，默认值 1 让存量行零改动；
   更新走 `... WHERE id=$1 AND version=$2 RETURNING version`（影响行数为 0 即冲突）。
3. **缺索引按实测清单一次性补齐**，索引名统一 `idx_<table>_<col>` 前缀，便于清单与代码互查。
4. **回滚契约落成可执行文件**：`db/migrations/down/NNN_*.down.sql`，由 `scripts/migration-drill.mjs`
   在一次性演练库上跑「正向 → 回滚 → 再正向」并逐条断言对象消失/复原。
   `down/` 是子目录，`verify-migrations` 与 `check-schema-fresh` 的 `*.sql` 扫描天然跳过，不会误当迁移。
5. **索引清单从 DDL 文本生成**（`scripts/db-index-inventory.mjs`），而不是查库：
   这样工件能进 CI，且和迁移保持同一事实源；`--check` 模式在漂移时失败。

## 3. 备选方案与为什么不选

| 备选 | 说明 | 否决理由 |
|---|---|---|
| A. 给所有 91 张表都加 `created_by/updated_by` | 字段齐整 | 学习者的行为数据没有"运营编辑者"概念，列永远为空，白占存储还误导 |
| B. 乐观锁用 `xmin` 系统列 | 零迁移 | 语义脆弱（`VACUUM FULL`/逻辑复制会变），且 SQL 可读性差，排查要懂系统列 |
| C. 把回滚写在 up 迁移末尾的注释里 | 省文件 | 注释不可执行，等于没有；本 ADR 的核心就是把"可回滚"变成可断言 |
| D. 索引清单手工维护一份 Markdown | 直观 | 必然与迁移漂移（本次就是因为"文档没写"才发现漏了 13 条索引） |

## 4. 影响与验收

- 正向：`node scripts/check-schema-fresh.mjs` 通过（schema.sql + 全部迁移收敛）；`node scripts/verify-migrations.mjs` 通过。
- 回滚：`node scripts/migration-drill.mjs` 通过（29 个对象回滚后消失、再正向全部复原）。
- 工件：`content-platform/db/index-inventory.md` 由 `pnpm db:inventory` 再生，`--check` 入 `test:scripts`（CI）。
- 兼容：全部 `ADD COLUMN IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` / `DO $$ ... duplicate_object`，重复执行为 no-op，存量数据零改动。

## 5. 后续（未在本阶段闭合）

  当前没有面向运营的编辑入口，先落数据层与契约，避免"先写无人调用的抽象"。
