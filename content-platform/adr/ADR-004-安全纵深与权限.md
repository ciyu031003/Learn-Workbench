# ADR-004：安全纵深、角色模型与操作审计

- **状态**：已采纳
- **日期**：2026-10-11
- **阶段**：组三 · 阶段 17（V3 横轨 H3）
- **相关文件**：`db/migrations/065_roles_and_audit.sql`、`db/migrations/down/065_roles_and_audit.down.sql`、
  `apps/web/lib/roles.ts`、`apps/web/lib/audit.ts`、`apps/web/lib/internal-guard.ts`、
  `scripts/lib/content-source.mjs`（`assertSafeRepoUrl` / `assertSafeGitRef` / `assertSafeRelativePath`）、
  `scripts/crawl_content_source.mjs`、`content-platform/security/checklist.md`

## 1. 背景（实测依据）

- 权限只有一个布尔 `users.is_admin`；受限操作**无审计留痕**（谁在什么时候导入了什么，查不到）。
- `scripts/crawl_content_source.mjs` 用 `execFileSync("git", ["clone", url, ...])`，`url` 来自
  `content_source.url`，`ref` 可来自 `--ref`：
  - `git` 支持 `ext::` 传输 → 诱饵 URL 可直接转成**命令执行**；
  - `--ref=--upload-pack=/tmp/evil.sh` 会被当成 git 选项（argv 不经 shell 也一样中招）。
- 读文件用 `path.join(repoDir, rel)` 且 `rel` 来自 `items[].path`（客户端可控），没有穿越校验。

## 2. 决策

1. **角色以 `users.role` 表达**（`learner` / `editor` / `reviewer` / `admin`），
   **保留 `is_admin` 并视为 admin**：不改老脚本、不动既有鉴权分支，避免"为了整齐"制造回归。
   `roleOf` 对未知用户与脏数据一律返回 `learner`（默认拒绝），`hasRole(null)` 直接 false。
2. **审计 best-effort**：`writeAuditLog` 失败只记 ERROR，不连带打挂业务写；
   高危操作可传 `required: true` 走硬失败。`actor_id` 用 `ON DELETE SET NULL` —— 人删了审计还在。
3. **内部接口统一前门，且顺序是"先限流再验密钥"**：反过来的话，错误密钥的探测可以无限次做字符串比较。
   前门额外支持"指定角色的登录用户"（内容编辑可在浏览器里跑 dry-run），actor 一并进审计。
4. **git 调用统一走 `runGit`**：`GIT_ALLOW_PROTOCOL=https` + `GIT_TERMINAL_PROMPT=0`，
   并且 `url` 过宿主白名单、`ref` 过形状校验、读盘路径过穿越校验。

## 3. 备选方案与为什么不选

| 备选 | 说明 | 否决理由 |
|---|---|---|
| A. 用多个布尔列（`is_editor`/`is_reviewer`…） | 改动小 | 组合爆炸，无法回答"谁能发布"；每次加角色都要改列与全部判断 |
| B. 完整 RBAC（roles/permissions/role_permissions 三表） | 最标准 | 当前只有 4 个角色、1 个后台，三表 + 权限点是过度设计；真需要时可由 `role` 平滑升级 |
| C. 审计写失败就 500 | 强一致 | 审计表抖动会连带业务不可用；此处可用性优先，且失败有 ERROR 日志可追 |
| D. 只做 URL 白名单、不做 ref 校验 | 少改一处 | ref 选项注入是**命令执行**级别，必须一并堵 |
| E. 让应用完全不做 git 操作（改成 HTTP 下载 zip） | 攻击面更小 | 现有 CLI 与报告链路都基于 clone；本次先把风险闸门补齐，迁移到 zip 作为后续可选优化 |
