# ADR-NNN：<一句话结论式标题>

- **状态**：提议 | 已采纳 | 已被 ADR-NNN 取代 | 已废止
- **日期**：YYYY-MM-DD
- **阶段**：组 X · 阶段 N（V3 轨 H? / Phase ?）
- **相关文件**：迁移号、源码路径、工件路径（写具体路径，不写"相关模块"）

## 1. 背景（真实代码或实测依据）

写**可核对**的事实：文件路径 + 行号级别的定位、迁移编号、查询出的数字、报错原文。
不要写"我们觉得"。若是"现状没有 X"，要说明是怎么确认的（例如"查 `pg_catalog` 得到"）。

## 2. 决策

编号列出决策点，每条一句话能读懂、能被实现、能被验收。

## 3. 备选方案与为什么不选

| 备选 | 说明 | 否决理由 |
|---|---|---|
| A | | |
| B | | |

至少要有一个**真被考虑过**的备选；"没想到别的"不是理由。

## 4. 影响与验收

- 正向 / 回滚怎么走；
- 哪些命令/测试能证明它成立（写成可复制的命令）；
- 兼容性与数据影响（存量数据要不要改、能不能零改动）。

## 5. 后续（未在本阶段闭合）

诚实列出没做完的部分与触发条件（"等出现第二个 X 时再做"），不要用"后续优化"糊过去。
