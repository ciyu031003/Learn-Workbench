地址三段划分：这是 408 必考的计算

主存地址 = 标记 tag | 组号/行号 (索引) | 块内偏移　计算顺序是从右往左：
① 块内偏移位数 = log₂(块大小)（决定块内第几个字/字节）；
② 索引位数 = log₂(Cache 的行数 / 每组行数) = log₂(组数)（决定落到哪一组）；
③ 标记位数 = 地址总位数 − 索引位数 − 偏移位数（剩下的高位才是 tag，用来判断"是不是我要的那一块"）。
例：32 位地址、16 行、4 字/块、4 路组相联 → 组数 = 16/4 = 4 → 索引 2 位；块大小 4 字 = 2² 字 → 偏移 2 位；tag = 32−2−2 = 28 位。

三种映射方式对比

直接映射：组数 = 行数，每个主存块只能放到唯一一行（行号 = 块号 mod 行数）。硬件最简单、比较器只需 1 个、命中时间最短；但两个块号之差恰为行数整数倍时会反复互相替换 → 冲突缺失严重，命中率最低。
全相联：只有一个组（索引 0 位），任何块可放入任意行。命中率最高、冲突缺失为 0；但需要与所有行的 tag 并行比较（行数越多比较器越贵越慢），替换算法也最复杂，只适合小容量 Cache（如 TLB、一级指令 Cache 的小配置）。
组相联（n 路）：折中方案。块先按索引定到唯一的一组，组内可选任意一行 → 组内冲突被消除，同时比较器只需 n 个。2 路/4 路组相联的命中率已经非常接近全相联，而硬件代价远低于全相联，所以现代 CPU 的 L1/L2/L3 几乎都用组相联（常见 8 路、16 路）。

三种缺失（3C）的区别

强制缺失（冷启动缺失）：该块第一次被访问，Cache 里必然没有，任何映射方式都无法避免，只与程序的首次访问有关。
冲突缺失：块其实在 Cache 里"放开"放得下，但被映射方式限制住了——直接映射时多个块竞争同一行，或组相联时竞争同一组。本演示切换"相联度"即可看到：相联度越高，冲突缺失越少（用同一个序列切换 1 路 / 2 路 / 4 路 / 全相联对比命中率）。
容量缺失：Cache 确实太小，某个块被换出后又被访问，此时即使换成全相联也一定会缺失。判断方法：本演示中若某次缺失在全相联下同样会发生，那就是容量缺失；若只有低相联度才发生，那就是冲突缺失。

为什么组相联是折中方案？

命中时间由"索引定位 + tag 比较"决定：直接映射比较 1 个 tag 最快，全相联要比较全部行最慢；组相联只在组内并比较少数几个 tag。2 路组相联就能消除绝大部分直接映射的颠簸（thrashing），代价只增加一个比较器；再往上加路的收益递减，却使比较器和替换逻辑变复杂。加上 LRU/FIFO 等替换算法能在组内选择牺牲行，组相联在"成本、速度、命中率"三者间取得了最好的平衡。

其他要点

① 块大小也在折中：块越大越能利用空间局部性（减少强制缺失），但块数变少、冲突加剧，且每次缺失要搬运更多数据、增加缺失代价。
② 替换算法：LRU 效果好但需要记录使用顺序（本表"最近使用"列即 LRU 计数），全相联下实现代价高；FIFO 简单但可能出现 Belady 异常（增加行数反而命中率下降）；直接映射无需替换算法（牺牲行唯一）。
③ 写策略：写直达 + 写不分配，或写回 + 写分配（配合"脏位"）。本演示只关心读访问的映射与替换。
