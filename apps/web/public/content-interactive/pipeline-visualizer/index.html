流水线为什么能提速？

把一条指令的执行切成 5 段，段间用寄存器隔离，让不同指令的不同阶段同时工作。理想情况下每个时钟周期都有一条指令完成，于是 n 条指令只需 T = n + k − 1 = n + 4 个周期（k 为段数），而串行执行需要 n × k 个周期。
由此得到三个 408 常考指标：吞吐率 TP = n / T（条/周期）；加速比 S = 串行时间 / 流水线时间 = nk / T；效率 E = 时空图有效面积 / 总面积 = nk / (k·T) = n / T = S / k。当 n → ∞ 时 T ≈ n，于是 TP → 1（每周期一条），S → k = 5，E → 1——这就是流水线的理论极限：加速比不超过段数。

冒险为什么会降低效率？

理想公式 T = n + 4 的前提是"每个周期每段都有活干"。一旦出现冒险，某些段就必须空转（插入气泡/停顿），占用时钟周期却不完成有效工作：T 变大 → TP、S、E 全部下降。冒险分三类：
① 结构冒险（资源冲突）：硬件部件不够用。本演示只设一个存储器，而"IF 取指令"和"MEM 取数据"都要访问它，若同一周期两者相撞（如 load 的 MEM 与下一条指令的 IF 重合）就必须让其中一方等待。解决办法：指令存储器与数据存储器分开（哈佛结构 / 分离 Cache），或让部件全流水化。切换上面的序列即可看到红色冲突框。
② 数据冒险（RAW）：后一条指令要用前一条还没写回的结果。例如 add r1,r2,r3 紧跟 sub r4,r1,r5，r1 要到第 5 周期的 WB 才写回，而 sub 在第 3 周期 EX 就要读 r1。若什么都不做，只能让 sub 一直等到 add 写回，插入 3 个气泡；数据旁路/转发则把 EX/MEM、MEM/WB 流水寄存器的结果直接送进 ALU 输入端，使 sub 只需等 1 个周期（ALU 结果在 EX 末尾就可用）。load-use 是特例：load 的数据要到 MEM 段结束才有，转发也救不了，必须硬停 1 个周期（本演示会把这条关键路径标紫）；若把 load 与其使用者拉开一条无关指令的距离（指令调度），这 1 个周期也能省掉。
③ 控制冒险：分支指令要等到 EX（甚至 MEM）才知道跳不跳，而 IF 早就按顺序取来了后面几条指令。若分支真的跳转，这些指令就是错的，必须清除（flush）并重新从目标地址取指——演示中把它们标红并加 2 个气泡。解决办法：分支预测（预测不跳转则顺序取指，猜对 0 代价、猜错照样清除；预测跳转则相反，适用于循环回边）、延迟槽（在分支后固定插一条无论跳不跳都要执行的指令，把它排到延迟槽里就完全消除了气泡）、以及提前在 ID 段完成分支判断并计算目标地址。

旁路为什么能减少停顿？

停顿的本质是"结果还没算出来，但使用者已经要读了"。不转发时，结果只能沿 WB 写回寄存器堆后才被读到，等待时间长；转发则抄近路，把 ALU 输出（EX/MEM 寄存器）或内存读出数据（MEM/WB 寄存器）直接从内部总线送到需要它的 ALU 输入，绕开了"必须等写回"这条长路径，把等待从 3 个周期压到 0~1 个周期。代价是要增加旁路通路和比较电路（判断源寄存器号是否匹配），但远比多停几个周期划算——所以现代处理器普遍采用转发 + 少量必要停顿。

其他说明

本演示假设：每段恰好 1 个周期、允许同一周期写后读、采用"取指与访存共用存储器"的结构；指令集简化为 add/sub/and/or/lw/sw/beq/bne/j，寄存器名 r0~r7。切换"数据冒险/控制冒险"下拉框可在同一序列上对比不同解决策略的周期数、吞吐率与加速比，这正是 408 大题里常考的比较点。
