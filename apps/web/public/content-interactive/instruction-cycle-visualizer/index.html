指令周期为什么要分成若干阶段？

CPU 执行一条指令，要依次完成“取指令 → 分析指令 → 取操作数 → 运算 → 送结果 → （必要时）保存断点”这些事。为了便于控制，教材按是否访问主存、访问几次把整个过程划分成若干个机器周期（CPU 周期），再把每个机器周期内的动作分解为微操作——微操作是不可再分的最小动作，由控制器发出的微命令驱动数据通路完成。四个阶段各自的目的是：
① 取指周期（FE）：任何指令都有的公共阶段。完成 (PC)→MAR、M(MAR)→MDR、(MDR)→IR、(PC)+1→PC，目的是把一条指令取进 IR，并让 PC 指向下一条指令。
② 间址周期（IND）：只有间接寻址指令才有。完成 Ad(IR)→MAR、M(MAR)→MDR、(MDR)→Ad(IR)，目的是把形式地址换成有效地址。
③ 执行周期（EX）：按指令功能完成运算或传送。以 ADD 为例：Ad(IR)→MAR、M(MAR)→MDR、(MDR)+(ACC)→ACC。
④ 中断周期（INT）：仅在响应中断时出现，执行的是硬件自动产生的中断隐指令——保存断点、把中断服务程序入口送入 PC。
所以 指令周期 = 取指周期 + [间址周期] + 执行周期 + [中断周期]，其中间址与中断是可选的，这正是“指令周期长短不一”的根本原因。

微命令、微操作、微指令、微程序是什么关系？

微命令是控制器向执行部件发出的最基本控制信号（如“打开 PC 输出门”“MAR 打入”）；微操作是在微命令控制下执行部件完成的一个动作，两者一 一对应（(PC)→MAR 就是一个微操作）。同一节拍内可以同时发出多个相容的微命令（互斥的微命令不能同拍发出，例如不能让两个寄存器同时向总线输出），这些相容微命令的集合构成一条微指令——也就是控制存储器 CM 中的一个字；完成一条机器指令所需的全部微指令构成一个微程序。
由此得到两种控制器实现：
· 硬布线控制器：不用 CM，直接由组合逻辑门电路按节拍电位（T1、T2…）和节拍脉冲产生控制信号。速度快，但逻辑一经设计就难以修改，适合指令少而规整的 RISC。
· 微程序控制器：控制信号存放在 CM 中，逐条取出微指令（CMDR）再译码，按 CMAR 给出的微地址取下一条。速度较慢（每条微指令都要访问一次 CM），但规整、易设计、易修改，适合指令复杂多样的 CISC。
切换到上面的“微程序”视角，可以看到每个节拍被当作一条微指令，并给出微地址（CMAR）、微指令内容（CMDR = 操作控制字段 + 下址字段）以及下址的形成方式：顺序 +1、下址字段直接给出、由机器指令操作码经微地址形成部件产生入口地址、以及由条件测试产生分支。

定长指令周期与不定长指令周期

定长（同步控制）：所有机器周期占用相同的节拍数（本演示取各阶段所需的最多节拍数），时序规整、控制简单，但微操作少的阶段只能空转。例如立即寻址 ADD 的执行周期只需要 1 个微操作，定长模式下仍要占满 4 个节拍，总节拍数明显变多。
不定长（异步控制）：每个机器周期按实际需要执行，做完即结束（靠“回答”信号确认），效率高、总节拍数少，但控制复杂、时序不规整。
把上面的开关在两种模式间切换，观察总节拍数的变化，就能直观理解这一考点。

为什么 (MDR)+(ACC)→ACC 要“分时”进行？

本演示采用单总线（内部总线）结构：所有寄存器都挂在同一条内部总线上，同一时刻只允许一个部件向总线发送数据。因此 ALU 的两个操作数不能同时上总线，必须先经暂存器 T 暂存第一个操作数，再读第二个操作数，最后 ALU 一起运算并把结果经总线送回 ACC——这就是为什么“加数在 MDR、被加数在 ACC”，却仍要分成几个节拍完成的原因。

需要注意的细节

① PC 与 MAR 都只有“地址”这一种含义，但 PC 是程序员可见的，MAR、MDR、IR 都是不可见的；② 取指周期的微程序是所有指令共用的公共微程序，在 CM 中只存一份，算 CM 容量时不要重复计算；③ 中断隐指令由硬件自动完成，不由程序指令给出，其功能是保存断点、寻找中断服务程序入口（并可能关中断）；④ 本例中的“＋1”表示加上一条指令的长度，定长指令字时每加一次即指向下一条指令。
