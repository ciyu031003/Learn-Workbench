基本思想：分块查找（又称索引顺序查找）是顺序查找与折半查找的折中。把长度为 n 的查找表分成 b 块、每块 s 个元素（n = b·s），要求块间有序、块内无序——后一块中的所有元素都大于前一块中的最大元素，但每块内部可以是乱的。为每块建立一个索引项（该块的最大关键字 + 该块的起始下标），所有索引项按最大关键字递增排列，构成索引表（索引顺序表）。
查找分两步：① 确定所在块：在索引表中找到第一个「最大关键字 ≥ k」的索引项，因为块间有序，这一步一旦命中就能断定 k 属于哪一块（索引表本身有序，所以既可以顺序查找，也可以折半查找）；② 块内查找：在该块内用顺序查找，逐个比较。两次查找的级别不同：索引表可以折半，块内只能顺序——块内无序，即使遇到的元素已经比 k 大也不能停，必须比完整块才能判定"该块中没有 k"。
ASL 推导（索引表顺序查找）：设等概率假设（每个元素被查概率 1/n，每个索引项被选中概率 1/b）。
· 索引表部分：比较第 1、2、…、b 项的次数分别是 1、2、…、b，成功时的平均比较次数 = (1+2+…+b)/b = (b+1)/2；
· 块内部分：块内顺序查找命中第 1、2、…、s 个元素的次数分别是 1、2、…、s，平均 = (1+2+…+s)/s = (s+1)/2；
· 相加得 ASL成功 = (b+1)/2 + (s+1)/2 = (b+s)/2 + 1（因为 n = b·s，也可写成 ½(n/s + s) + 1）。
最优分块：把 b = n/s 代入，ASL = (n/s + s)/2 + 1。由均值不等式 n/s + s ≥ 2√(n/s·s) = 2√n，当且仅当 s = b = √n 时取等号，此时 ASLmin = √n + 1。例：n = 10000、s = b = 100 时 ASL = 101，而顺序查找要 (10000+1)/2 ≈ 5000 次。
ASL 失败（近似）：失败时索引表仍要比较到"第一个最大关键字 ≥ k"的索引项（顺序查找平均 (b+1)/2 次），进入该块后又必须把整块比完 s 次才能断定不存在，故 ASL失败 ≈ (b+1)/2 + s。特例：当 k 比所有块的最大关键字都大时，索引表比完 b 次即可判定失败，连块都不进入（演示里选"查找失败示例"或把 k 调大即可看到这两种失败）。
索引表改用折半查找：索引部分由 (b+1)/2 降到 ⌈log₂(b+1)⌉ 量级（教材也写作平均约 log₂(b+1) − 1 的近似形式，以上界写法为准），于是 ASL成功 = ⌈log₂(b+1)⌉ + (s+1)/2，ASL失败 ≈ ⌈log₂(b+1)⌉ + s。注意折半只能优化"确定块"这一步，块内那 (s+1)/2 次一分也省不掉——所以分块查找的优化重点是"让 b 和 s 尽量接近 √n"。
适用条件：① 表必须分块有序（块间有序），块内可以无序；② 通常要求顺序存储（便于按下标定位到块首）；③ 特别适合"既要查得快、又要能动态插删"的场景：插入时只需把元素放进合适的块、必要时重建索引，不必像折半查找那样移动大量元素。
与其它查找方法的对比：顺序查找 ASL = (n+1)/2，不要求有序、链表也能用，但慢；折半查找 ASL ≈ log₂(n+1) − 1，最快，但要求整表有序 + 顺序存储，插删代价大；分块查找 ASL 介于两者之间（最优 √n + 1），插删较方便；二叉排序树平衡时 ≈ log₂n；散列表理想情况 ≈ 1。典型考法：n = 400、每块 10 个元素（b = 40），用顺序查找确定块，则 ASL成功 = (40+10)/2 + 1 = 26；换成折半查找确定块则为 ⌈log₂41⌉ + (10+1)/2 = 6 + 5.5 = 11.5。
